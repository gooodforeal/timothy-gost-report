# Формат папки plain

```
plain/
├── style.json             необязательно: отличия от ГОСТ по умолчанию
├── 01_vvedenie.md         файлы собираются в порядке имён
├── 02_teoriya.md
├── 03_realizaciya.md
├── 04_zakljuchenie.md
├── 05_istochniki.md
├── 06_prilozhenie_a.md
└── images/                картинки (PNG, JPG, GIF, BMP, TIFF; SVG не поддерживается)
```

Один файл — один раздел первого уровня, так их проще править и переставлять.
Номера разделов, рисунков, таблиц и приложений скрипт ставит сам. **Номера
вручную в тексте не пишите**, только метки.

Титульного листа в `plain/` нет: его делают отдельно.

Готовый docx скрипт кладёт в папку `out/` рядом с `plain/` (по умолчанию
`out/report.docx`) и создаёт её сам.

## style.json

Файл нужен, только если методичка расходится с ГОСТ. В нём пишутся только
отличающиеся ключи, полный список — в `gost-rules.md`:

```json
{
  "margin_right_mm": 10,
  "caption_numbering": "by_section",
  "first_page_number": 2
}
```

Опечатка в ключе или значение не того типа — это ошибка сборки, а не молчаливое
игнорирование.

## Синтаксис Markdown

### Заголовки

Все заголовки выводятся одинаково: полужирные, по левому краю с абзацного
отступа, без капса, с интервалом 0 пт сверху и снизу. Пишите их обычным регистром.

```markdown
# Введение                         → «Введение» (структурный элемент, без номера)
# Анализ предметной области        → «1 Анализ предметной области»
## Обзор аналогов                  → «1.1 Обзор аналогов»
### Сравнение по цене              → «1.1.1 Сравнение по цене»
# Цель работы {-}                  → раздел без номера (для лабораторных)
# Проектирование {#sec:design}     → метка; ссылка [@sec:design] даст «2»
# Приложение: Исходный код {#app:code}  → «Приложение А. Исходный код»; [@app:code] → «А»
```

- Уровней не больше трёх (`####` — ошибка).
- Структурные элементы скрипт узнаёт по тексту: Введение, Заключение, Реферат,
  Аннотация, Термины и определения, Перечень сокращений и обозначений,
  Список использованных источников / литературы, Библиографический список,
  Список исполнителей. Регистр приводится к виду «Введение».
- `# Содержание` писать нельзя: оно генерируется.
- Буквы приложений ставятся автоматически по порядку (А, Б, В, Г, Д, Е, Ж, И, К…).

### Абзацы и выделения

Абзац — это строки подряд, разделитель — пустая строка. Внутри абзаца:
`*курсив*` (переменные в тексте) и `` `код` `` (имена функций, файлов, команд;
выводится шрифтом Consolas). `**полужирный**` поддерживается, но по ГОСТ в тексте
его быть не должно, и `check_text.py` на него ругается.

### Списки

```markdown
Для этого нужно было:

- описать сущности предметной области;
- выбрать формат ответа;
  - вложенный пункт (отступ 2 пробела);
- проверить производительность.

1. первый шаг;     → 1) первый шаг;
2. второй шаг.     → 2) второй шаг.
```

В разделе «Список использованных источников» нумерованный список выводится как
«1.», «2.».

### Рисунки

```markdown
![Схема базы данных](images/er.png){#fig:er width=15}
```

- Подпись обязательна. Получится «Рисунок 3 — Схема базы данных».
- `width` — ширина в сантиметрах (не больше 16,5 при стандартных полях). Без
  `width` рисунок вставляется в натуральном размере, но не шире текста.
- Ссылка в тексте: `на рисунке [@fig:er]` → «на рисунке 3».

### Таблицы

```markdown
Таблица: Сравнение СУБД {#tbl:dbms}

| СУБД | Лицензия | Максимальный размер БД |
|---|---|---|
| PostgreSQL | PostgreSQL License | не ограничен |
| SQLite | Public Domain | 281 ТБ |
```

- Строка `Таблица: …` обязательна и стоит прямо над таблицей.
- Первая строка таблицы — шапка, она повторяется на каждой странице.
- `\|` — вертикальная черта внутри ячейки.
- Ссылка: `в таблице [@tbl:dbms]`.

### Листинги

````markdown
Листинг: Функция расчета стоимости {#lst:total}

```python
def total(items: list[Item]) -> Decimal:
    return sum(item.price * item.quantity for item in items)
```
````

- С подписью `Листинг: …` получится «Листинг 2 — Функция расчета стоимости»,
  код набирается Consolas 12 пт.
- Без подписи будет просто моноширинный блок без номера (для команд терминала).
- Большие листинги (больше ~40 строк) выносите в приложение, в тексте оставляйте
  фрагмент.

### Формулы

```markdown
$$ *S* = Σ *p*ᵢ · *q*ᵢ $$ {#eq:total}

где *p*ᵢ – цена позиции, руб.; *q*ᵢ – количество, шт.
```

- Формула записывается одной строкой с Unicode-символами (Σ, ·, ², ₁, ≤, √, α,
  π, →). LaTeX не поддерживается. Переменные пишутся `*курсивом*`.
- Номер «(1)» ставится у правого края; `[@eq:total]` в тексте → «(1)».

### Разрыв страницы

`\newpage` на отдельной строке. Обычно он не нужен: разделы и приложения и так
начинаются с новой страницы: каждый заголовок первого уровня (`#`)
всегда открывает новую страницу.

### Ссылки на источники

Пишутся обычным текстом: `[1]`, `[2, с. 45]`. Нумеруйте в порядке первого
упоминания и следите, чтобы они совпадали со списком.
