# timothy-gost-report — отчёт по ГОСТ в docx

Пользователь получает готовый `.docx` без титульного листа: титульник делают
отдельно. Исходник отчёта — папка `plain/` с Markdown-файлами. docx всегда
собирается из неё скриптом, **docx руками не редактируется**. Любая правка —
это изменение `plain/` и пересборка. Готовый docx всегда лежит в папке `out/`
рядом с `plain/`.

Скрипты лежат рядом с этим файлом:

- `scripts/build_report.py` — сборка docx из `plain/`, здесь вся вёрстка по ГОСТ;
- `scripts/check_text.py` — поиск ИИ-штампов и нарушений оформления в тексте;
- `scripts/plain_parser.py`, `scripts/report_style.py` — модули сборщика.

Справочники (читай по мере надобности):

- `references/plain-format.md` — **обязательно** перед написанием `plain/`: синтаксис
  заголовков, рисунков, таблиц, листингов, формул, ссылок и `style.json`;
- `references/writing-style.md` — **обязательно** перед написанием текста: как
  писать, чтобы текст не выглядел сгенерированным;
- `references/gost-rules.md` — требования к оформлению: что делает скрипт, что
  контролирует агент, библиография, типовые структуры отчётов;
- `examples/plain/` — рабочий пример папки plain (лабораторная работа).

В разговоре с пользователем и в тексте отчёта не называй номер конкретного
стандарта: пиши просто «по ГОСТ». Если методичка ссылается на конкретный
стандарт, оформление берётся из методички.

## Параметры оформления (по умолчанию)

| Что | Значение |
|---|---|
| Лист, поля | A4; левое 30 мм, правое 15 мм, верхнее и нижнее 20 мм |
| Основной текст | Times New Roman 14 пт, чёрный, интервал 1,5, абзацный отступ 1,25 см, по ширине |
| Заголовки (все, включая Введение, Заключение, Приложения, Содержание) | полужирные, 14 пт, **по левому краю с абзацного отступа 1,25 см**, обычным регистром (не капсом), без точки в конце; **отступы сверху и снизу 0 пт** |
| Нумерация заголовков | «1 Название», «1.1 Название», «1.1.1 Название»; Введение, Заключение и Список источников без номера |
| Новая страница | **каждый заголовок первого уровня (`#`) — с новой страницы**, всегда, без исключений |
| Рисунки | по центру, подпись снизу по центру «Рисунок 1 — Название» |
| Таблицы | подпись сверху слева «Таблица 1 — Название»; текст 12 пт, интервал 1; шапка повторяется |
| Листинги | подпись сверху слева «Листинг 1 — Название»; **Consolas 12 пт**, интервал 1, без отступа |
| Формулы | по центру, номер «(1)» у правого края |
| Приложения | «Приложение А. Название», с новой страницы; нумерация внутри «А.1» |
| Номера страниц | внизу по центру на всех страницах; с 1 или с 2, если титульник вставят отдельно |
| Содержание | автоматическое поле Word с номерами страниц |
| Титульный лист | не генерируется |

Любой параметр переопределяется в `plain/style.json` под методичку (ключи —
в `references/gost-rules.md`).

## Порядок работы

### 1. Собрать вводные

От пользователя нужно: **вид отчёта** (лабораторная, практика, курсовая,
реферат, НИР), **тема, номер работы, вариант**, **список разделов** (если задан)
и **методички и материалы** (PDF, DOCX, ссылки, код, результаты, скриншоты).

- Прочитай все материалы целиком. Из методички выпиши обязательную структуру,
  требования к оформлению, которые **отличаются** от параметров по умолчанию
  (поля, кегль, нумерация рисунков), и требования к содержанию разделов.
- Если нужны подробности правил — смотри `references/gost-rules.md`. Если нужного
  момента там нет, найди правила оформления отчётов по ГОСТ в интернете.
- Спроси, будет ли отдельный титульный лист перед отчётом. Если да, поставь
  `"first_page_number": 2`.
- Если не хватает содержательных данных (результатов измерений, варианта
  задания), спроси одним сообщением со списком.
- **Не выдумывай** результаты экспериментов, цифры, источники и скриншоты. Если
  работу (код, измерения) нужно сделать — сделай её по-настоящему или попроси данные.

### 2. Создать папку `plain/`

Папка создаётся в рабочей папке пользователя, если он не указал другую. Рядом
с ней лежит `out/` для готового docx:

```
out/                   готовый docx (создаётся скриптом при сборке)
plain/
├── style.json         необязательно: отличия от параметров по умолчанию
├── 01_vvedenie.md     один файл = один раздел первого уровня, порядок по имени
├── 02_....md
├── ...
├── NN_istochniki.md
├── NN_prilozhenie_a.md
└── images/            рисунки (PNG/JPG; SVG нельзя — конвертируй в PNG)
```

Синтаксис — строго по `references/plain-format.md`. Коротко:

- Каждый `#` (заголовок первого уровня) начинается с новой страницы, поэтому
  на `#` делай только крупные части отчёта, подразделы — через `##` и `###`.
- `# Введение` — структурный элемент; `# Анализ` → «1 Анализ»; `## Обзор` → «1.1 Обзор»;
  `# Цель работы {-}` — без номера; `# Приложение: Код {#app:code}` → «Приложение А. Код».
  Заголовки пиши обычным регистром.
- Рисунок: `![Подпись](images/x.png){#fig:x width=15}`.
- Таблица: строка `Таблица: Подпись {#tbl:x}` прямо над pipe-таблицей.
- Листинг: строка `Листинг: Подпись {#lst:x}` прямо над блоком ```` ```lang ````.
- Формула: `$$ *E* = *m* · *c*² $$ {#eq:x}`, затем «где …».
- Ссылки: `[@fig:x]`, `[@tbl:x]`, `[@lst:x]`, `[@eq:x]` (даст «(1)»), `[@app:x]`.
  Номера руками не пиши.

Рисунки: скриншоты и схемы от пользователя копируй в `images/`. Графики по
данным строй в matplotlib: белый фон, сдержанная палитра, подписи осей на
русском с единицами, шрифт с кириллицей, 150–200 dpi. Схемы рисуй в Graphviz или
matplotlib, если они доступны, иначе попроси пользователя.

### 3. Написать текст

Перед написанием прочитай `references/writing-style.md` и следуй ему. Главное:

- конкретика этой работы (вариант, цифры, имена файлов, что не получилось)
  вместо общих фраз, которые подойдут к любому отчёту;
- никаких «В современном мире», «Важно отметить», «играет ключевую роль» и
  «Таким образом» в конце каждого абзаца;
- связные абзацы разной длины, списки только для перечислимого, без троек;
- научно-технический, но живой стиль, без полужирного в тексте;
- на каждый рисунок, таблицу, листинг и приложение есть ссылка в тексте до него.

Объём ориентируй на методичку. Если он не указан: лабораторная 5–12 страниц,
отчёт по практике 15–25, реферат 15–20, курсовая 25–40.

### 4. Проверить текст и собрать

```bash
SKILL_DIR=<папка этого скилла, где лежит SKILL.md>
python3 "$SKILL_DIR/scripts/check_text.py" plain          # исправить замечания
python3 "$SKILL_DIR/scripts/build_report.py" plain -o "out/Отчет_ЛР3_Иванов.docx"
```

- `SKILL_DIR` — папка, из которой загружен этот SKILL.md. В зависимости от агента
  и способа установки это, например, `~/.claude/skills/timothy-gost-report`,
  `.claude/skills/timothy-gost-report` или `.agents/skills/timothy-gost-report`.
  Если путь неизвестен, найди его: `find ~ . -path '*timothy-gost-report/scripts/build_report.py' 2>/dev/null`.
- Нужен `python-docx` (Python 3.9+). Если его нет: `pip install python-docx`
  или запуск через `uv run --with python-docx python3 …`.
- Ошибки сборки имеют вид `файл.md:строка: причина`. Исправь `plain/` и пересобери.
- **Итоговый docx всегда кладётся в папку `out/`** рядом с `plain/` (скрипт
  создаёт её сам). Имя файла должно быть понятным: `out/Отчет_<что>_<Фамилия>.docx`.
  Без `-o` получится `out/report.docx`.

### 5. Проверить результат

Посмотри docx глазами, если есть чем отрендерить:

- LibreOffice: `soffice --headless --convert-to pdf --outdir out out/report.docx`;
- macOS с Word: через `osascript` открыть документ, выполнить `update fields (text object of document 1)`
  и `save as … file format format PDF`. Файлы для Word клади в
  `~/Library/Containers/com.microsoft.Word/Data/`, иначе песочница не пустит.
  Word при открытии может показать диалог («Обновить поля?», доступ к файлу) и
  перестать отвечать на AppleScript. Тогда не повторяй попытки в цикле: попроси
  пользователя закрыть диалог или проверь через pandoc.

Затем преврати PDF в картинки страниц (PyMuPDF) и проверь: рисунки не вылезают
за поля, таблицы читаются, пустых страниц нет. Если рендерить нечем, хотя бы
выполни `pandoc out/report.docx -t plain` и проверь порядок разделов и нумерацию.

### 6. Отдать пользователю

Сообщи путь к docx и коротко опиши структуру: сколько страниц, рисунков и
таблиц. Напомни, что при открытии Word может спросить «Обновить поля?» — нужно
ответить **Да**, тогда заполнится содержание. Можно и вручную: правый клик по
содержанию → «Обновить поле» → «целиком». Титульный лист пользователь
добавляет сам.

## Правки

Если пользователь просит что-то поменять, меняй **только** `plain/` (текст,
картинки, `style.json`) и запускай тот же скрипт. Новый docx сохраняется в `out/` с тем же
именем. Если файл открыт в Word, сохранение упадёт с понятной ошибкой — попроси
закрыть файл. Рисунки, таблицы и ссылки перенумеруются автоматически. Никогда не
правь docx напрямую: следующая сборка всё затрёт.
