# timothy-gost-report

Скилл для ИИ-агентов (Claude Code, Codex, Cursor и других, поддерживающих
[Agent Skills](https://vercel.com/kb/guide/agent-skills-creating-installing-and-sharing-reusable-agent-context)),
который пишет отчёты по ГОСТ и собирает из них готовый `.docx`: лабораторные,
курсовые, рефераты, отчёты по практике и о НИР.

Агент изучает задание и методичку, раскладывает содержимое по Markdown-файлам
в папке `plain/` и пишет текст живым языком без ИИ-штампов. Рядом в той же
папке лежат рисунки, таблицы, листинги и формулы. Встроенный Python-скрипт
собирает из `plain/` документ Word в папку `out/` со всей вёрсткой. Чтобы
что-то поправить, нужно изменить файлы в `plain/` и пересобрать отчёт.

## Установка

Через [skills CLI](https://github.com/vercel-labs/skills) (нужен Node.js):

```bash
npx skills add gooodforeal/timothy-gost-report
```

Полезные флаги:

```bash
npx skills add gooodforeal/timothy-gost-report --list          # показать скиллы в репозитории
npx skills add gooodforeal/timothy-gost-report -a claude-code  # поставить для конкретного агента
npx skills add gooodforeal/timothy-gost-report -g              # глобально, для всех проектов
```

Вручную для Claude Code:

```bash
git clone https://github.com/gooodforeal/timothy-gost-report ~/.claude/skills/timothy-gost-report
```

### Зависимости

- Python 3.9+;
- [`python-docx`](https://pypi.org/project/python-docx/): `pip install python-docx`.
  Если библиотеки нет, агент поставит её сам или запустит сборку через
  `uv run --with python-docx`.

## Использование

Достаточно попросить агента, например:

> Сделай отчёт по лабораторной работе №3 «Индексы в PostgreSQL» по дисциплине
> «Базы данных». Разделы: цель, теория, ход работы, выводы. Методичка в
> `docs/metodichka.pdf`, результаты замеров в `results.csv`.

Агент:

1. прочитает задание и материалы, выпишет требования методички;
2. создаст `plain/` с разделами в `.md`, картинками и (при необходимости) `style.json`;
3. проверит текст на ИИ-штампы (`check_text.py`);
4. соберёт `out/Отчет_….docx` (`build_report.py`) и проверит результат.

Чтобы что-то поменять, напиши агенту, что исправить. Он изменит `plain/` и
пересоберёт docx тем же скриптом.

Результат на диске:

```
plain/   исходник отчёта (Markdown, картинки, style.json)
out/     готовый .docx
```

## Оформление по умолчанию

| Что | Значение |
|---|---|
| Лист, поля | A4; левое 30 мм, правое 15 мм, верхнее и нижнее 20 мм |
| Текст | Times New Roman 14 пт, интервал 1,5, абзацный отступ 1,25 см, по ширине |
| Заголовки | полужирные, по левому краю с абзацного отступа, не капсом, интервал 0 пт сверху и снизу |
| Новая страница | каждый заголовок первого уровня |
| Нумерация | разделы «1», «1.1», «1.1.1»; Введение, Заключение и Список источников без номера |
| Рисунки | по центру, подпись снизу: «Рисунок 1 — Название» |
| Таблицы | подпись сверху слева: «Таблица 1 — Название», текст 12 пт, шапка повторяется |
| Листинги | «Листинг 1 — Название», Consolas 12 пт, интервал 1 |
| Формулы | по центру, номер «(1)» у правого края |
| Приложения | «Приложение А. Название», нумерация внутри «А.1» |
| Содержание | автоматическое поле Word |
| Номера страниц | внизу по центру |
| Титульный лист | не генерируется, его делают отдельно |

Отличия под конкретную методичку задаются в `plain/style.json`:

```json
{
  "margin_right_mm": 10,
  "caption_numbering": "by_section",
  "first_page_number": 2
}
```

Полный список ключей — в [references/gost-rules.md](references/gost-rules.md).

## Ручной запуск скриптов

Агент вызывает их сам, но их можно запускать и без него:

```bash
python3 scripts/check_text.py plain                          # проверка текста
python3 scripts/build_report.py plain -o out/report.docx     # сборка docx
```

Попробовать на примере:

```bash
python3 scripts/build_report.py examples/plain -o out/example.docx
```

## Структура репозитория

```
SKILL.md                    инструкция для агента (точка входа скилла)
scripts/
  build_report.py           сборка docx из plain/
  plain_parser.py           разбор Markdown, нумерация, перекрёстные ссылки
  report_style.py           параметры оформления и style.json
  check_text.py             поиск ИИ-штампов и нарушений оформления в тексте
references/
  plain-format.md           синтаксис файлов в plain/
  gost-rules.md             правила оформления, библиография, структуры отчётов
  writing-style.md          как писать, чтобы текст не выглядел сгенерированным
examples/plain/             пример исходника лабораторной работы
```

## Ограничения

- Шрифты Times New Roman и Consolas должны быть установлены там, где docx
  открывают. На Windows они есть по умолчанию, на macOS Consolas ставится
  вместе с MS Office.
- Содержание заполняется, когда Word обновит поля: при открытии на вопрос
  «Обновить поля?» нужно ответить «Да». В LibreOffice: Сервис → Обновить → Всё.
- Формулы записываются Unicode-текстом (Σ, ², ₁, ≤), LaTeX не поддерживается.
- Изображения: PNG, JPG, GIF, BMP, TIFF; SVG нужно конвертировать в PNG.
